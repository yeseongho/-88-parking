🅿️ 올팍주차:88 | OLPARK Parking 88
올림픽공원 주차정보 통합 조회 및 AI 혼잡도 예측 서비스
공공데이터 기반 주차 현황 · 공연·날씨 연계 · 시간대별 AI 예측 · 주차장별 추천

📌 프로젝트 소개
올팍주차:88은 올림픽공원 방문자가 주차 상황을 확인하고 방문 시간을 계획할 수 있도록 개발한 개인 포트폴리오 웹 서비스입니다.

올림픽공원 공개 주차대수 조회 정보에 공연 일정과 기상 예보를 결합해 시간대별 혼잡도를 추정합니다. 또한 주차장별 위치와 시설 특성을 반영해 목적지에 맞는 주차 후보를 안내합니다.
중요: 본 서비스는 한국체육산업개발 또는 올림픽공원의 공식 서비스가 아닌 독립 개발 프로젝트입니다. 공개 API의 조회 시각과 원본 센서 측정 시각은 다를 수 있으며, AI의 예측 점수는 실제 입차 가능 여부를 보장하지 않습니다.

프로젝트 목표
1. 여러 곳에 흩어진 주차·공연·날씨 정보를 한 화면에서 확인할 수 있도록 통합
2. 시간대별 혼잡도 변화를 시각화해 방문 의사결정 지원
3. 공공 API의 과거 조회 이력을 누적하여 예측에 점진적으로 반영
4. 주차장별 시설 특성과 공연장 인접도를 활용한 추천 기능 구현

🖥️ 주요 기능
| 기능 | 설명 |
|---|---|
| **공식 주차현황 조회** | 공개 API에서 동2문·남2문·북2문 합산 주차대수를 조회하고 참고 기준 2,200대 대비 비율 표시 |
| **AI 시간대별 혼잡도** | 선택 날짜의 09~20시 혼잡 지수 및 방문 시간대 비교 |
| **현재 시간대 예측** | 한국시간 기준 현재 정시의 AI 추정 결과 표시 |
| **주차장별 추천** | 목적지 접근성, 공개 주차 규모, 시설 특성, 공연 영향으로 구역별 비교 지수 산출 |
| **공연·날씨 연동** | 공식 공연 목록 및 기상청 예보를 시나리오 입력값으로 사용 |
| **주차 이력 축적** | 조회 기록을 SQLite에 저장하고 날짜·요일·시간대별로 집계 |
| **누적 이력 반영** | 비슷한 요일·시간·기상·공연 조건의 과거 기록을 이후 예측에 점진적으로 반영 |

예측 처리 방식
1. 기본 시뮬레이션: 시간, 요일, 기온, 강수확률, 공연 정보를 입력하여 혼잡 지수 계산
2. 과거 이력 보정: 기록이 충분하면 유사한 날짜·시간 조건의 과거 공식 조회값을 가중 반영
3. 최근 현황 보정: 오늘의 가까운 시간대에 한하여 유효한 최근 공식 API 조회값을 추가 반영
4. 구역별 비교: 주차장별 공개 규모와 인접 시설, 공연 영향을 적용하여 상대적 추천 지수 산출
정확도 관련 주의사항: 기본 Random Forest는 가상 규칙으로 생성한 학습 데이터를 사용합니다. 과거 데이터 반영 기능은 실제 API 조회 기록을 활용하지만, 아직 실제 입차 가능 공간을 예측하는 성능이 독립적으로 검증된 모델은 아닙니다.

🚀 로컬 실행 방법
1. 저장소 내려받
git clone https://github.com/yeseongho/-88-parking.git
cd -- -88-parking

2. 백엔드 실행
cd backend
python -m pip install -r requirements.txt
python train_model.py
python -m uvicorn main:app --reload --port 8000

3. 프론트엔드 실행
별도 터미널에서 프로젝트 최상위 폴더로 이동한 뒤:
python -m http.server 8765
브라우저에서 http://127.0.0.1:8765 접속. 로컬 실행 시 config.js의 window.OLPARK_API_BASE는 빈 문자열로 유지합니다.

🧪 개발 과정에서 해결한 문제
01. 공식 주차현황과 AI 예측의 큰 격차
문제: 공식 API에서 주차대수가 높은 상황에도 시뮬레이션 모델이 낮은 혼잡도를 표시했습니다.

개선: 최근 공식 조회값의 유효기간과 예측 시점까지의 시간 차이를 고려하는 보정 로직을 추가했습니다. 실제 원본 측정 시각이 미제공이라는 한계도 함께 표시합니다.
02. 주차장별 예측값이 모두 동일하게 나오는 문제
문제: 공통 혼잡 지수만 사용하여 구역별 추천 정보의 차별성이 부족했습니다.

개선: 주차장별 규모, 인접 시설 유형, 목적지 접근성, 공연 시간대 영향을 결합해 서로 다른 비교 지수를 계산했습니다. 구역별 실제 잔여 대수로 표현하지는 않습니다.
03. 시간이 지나도 학습 데이터가 쌓이지 않는 문제
문제: 시뮬레이션 모델이 실제 공개 주차 조회 기록을 충분히 학습에 활용하지 못했습니다.

개선: SQLite에 API 조회 기록을 누적하고, 동일 날짜의 반복 조회를 시간 단위로 집계했습니다. 새로운 날짜 표본이 늘어날수록 이력 반영 비중을 높이도록 설계했습니다.
04. 잦은 화면 갱신으로 사용성이 저하되는 문제
문제: 주기적인 전체 페이지 갱신으로 사용자가 정보를 읽기 어려웠습니다.

개선: 전체 화면 자동 새로고침을 제거하고, 현재 시간대 AI 예측 카드만 정각에 갱신하도록 구성했습니다.

⚠️ 데이터 및 서비스 한계
- 공식 API의 조회 시각은 실제 센서 측정 시각과 다를 수 있습니다.
- 공개 주차대수는 일부 출입구의 합산값이며 구역별 실제 잔여 대수는 제공되지 않습니다.
- 2,200대는 별도 안내 자료의 참고 기준으로, API 응답 자체에 포함된 실측 총수용량이 아닙니다.
- 기상 조건은 예보값이며 해당 시간의 실제 관측 날씨와 다를 수 있습니다.
- 무료 호스팅의 일시 정지·저장소 초기화로 24시간 수집 및 장기 보존이 보장되지 않습니다.
- 방문 전에는 반드시 공식 올림픽공원 주차 안내를 확인해 주세요.
