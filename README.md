📍 Project Overview | 프로젝트 소개
올팍주차:88은 올림픽공원 방문자가 주차현황, 혼잡 예상 시간, 목적지별 주차 후보, 공연·날씨 정보를 한곳에서 확인할 수 있도록 만든 공공데이터 활용 웹 서비스입니다.

단순히 현재 주차대수를 보여주는 것에서 나아가, 공개 API 조회 기록을 축적하고 과거의 유사한 날짜·시간대 정보를 미래 예측에 점진적으로 반영하는 구조를 개발했습니다.
| 항목 | 내용 |
|---|---|
| 프로젝트명 | 올팍주차:88 (OLPARK Parking 88) |
| 개발 형태 | 개인 포트폴리오 프로젝트 |
| 서비스 대상 | 올림픽공원 방문객 |
| 핵심 분야 | 공공데이터 활용 · 백엔드 API · AI 예측 · 데이터 수집 |
| 배포 | GitHub Pages + Render Free Web Service |
| 서비스 URL | **https://yeseongho.github.io/-88-parking/** |
이 서비스는 올림픽공원 또는 한국체육산업개발의 공식 홈페이지가 아닌 독립 개발 프로젝트입니다. AI 예측치는 실제 주차 가능 대수나 입차를 보장하지 않습니다.

💡 기획 배경 및 문제 정의
올림픽공원에서는 공연·체육시설 이용 등 방문 목적에 따라 주차 수요가 달라질 수 있습니다. 방문자는 단순한 주차장 위치뿐 아니라 현재 주차가 얼마나 혼잡한지, 언제 방문하는 것이 좋을지, 목적지와 가까운 주차장이 어디인지 확인할 필요가 있습니다.

이 프로젝트는 다음 세 가지 문제에서 출발했습니다.
1. 분산된 정보: 주차대수, 공연 일정, 날씨를 각각 확인해야 하는 불편함
2. 시간대별 판단의 어려움: 현재 주차현황만으로 미래의 혼잡을 알기 어려움
3. 데이터 활용 부족: 한 번 조회한 주차현황을 버리지 않고 계속 축적할 필요성
목표: 공개정보를 통합하고, 시간에 따라 축적되는 데이터를 활용해 방문 판단을 돕는 서비스를 구현합니다.

⭐ Core Features | 핵심 기능
01. 공식 주차현황 통합 조회
- 공개 API에서 동2문·남2문·북2문 합산 주차대수 조회
- 별도 안내 자료의 참고 기준 2,200대 대비 비율 시각화
- 최근 조회 시각 표시 및 조회 실패 시 상태 구분
- API 조회 시각과 실제 센서 측정 시각이 다를 수 있음을 안내
02. AI 시간대별 혼잡도 예측
- 09:00~20:00의 시간대별 혼잡 예상 그래프
- 날짜·요일·기온·강수확률·공연 조건을 반영한 추정
- 현재 시간대의 정시 기준 예측 지수 제공
- 가까운 미래 예측에 유효한 최근 공식 조회값을 일부 반영
03. 주차장별 혼잡도 비교 및 추천
- K-아트홀, 올림픽홀, 수영장, KSPO DOME 등 인접 시설 기반 비교
- 공개된 구역별 주차 규모, 시설 특성, 공연 영향, 목적지 접근성을 고려
- 추천 후보 카드 강조 표시
- 실제 구역별 남은 주차대수 대신 상대적 혼잡 비교 지수 제공
04. 공연·날씨 정보 연동
- 공개된 공연 일정과 기상청 예보를 API로 조회
- 날짜에 따라 공연 건수 및 시간대별 영향 계산
- 공연이 확인되지 않거나 API가 실패한 경우를 구별하여 표시
05. 누적형 주차 데이터 분석
- 주기적으로 조회한 공식 API 응답을 SQLite에 저장
- 분 단위 기록을 날짜 × 시간 단위로 묶어 학습 표본 중복 방지
- 과거 같은 요일·시간대·날씨·공연 조건을 비교하여 예측에 반영
- 실제 기록이 늘수록 과거 데이터의 반영 비중을 점진적으로 조절
현재 AI 모델의 기본값은 가상 규칙 데이터를 이용한 시뮬레이션입니다. 과거 공개 API 기록을 이용한 보정 기능을 추가했지만, 실제 주차 가능 여부를 독립적으로 검증한 예측 모델은 아닙니다

🔍 주요 문제 해결 경험
문제 1. 실제 주차현황 90%대 vs AI 예측 20%대
원인: 초기 AI 모델이 가상 데이터로 학습되어 공식 API 조회값과 큰 차이가 발생했습니다.

해결: 모델의 기본 예측과 최근 공개 API 조회값을 구분한 뒤, 오늘의 가까운 시간대에서는 조회값의 유효기간과 예측 시간 차이에 따라 보정했습니다.

배운 점: 예측값을 단순히 보여주는 것보다 데이터의 출처, 갱신 시각, 한계를 명확히 표현하는 것이 중요했습니다.
문제 2. 주차장별 혼잡도 점수가 모두 같게 나오는 현상
원인: 모든 주차장에 동일한 전체 혼잡 지수를 적용하여 구역별 차이가 나타나지 않았습니다.

해결: 공개된 주차 규모와 시설 기본 수요, 공연장과의 관계 및 목적지 접근성 가중치를 분리해 적용했습니다.

배운 점: 전체 합산 데이터만으로 구역별 실측 점유율을 알 수는 없으므로, 결과를 실제 잔여 대수가 아닌 비교용 추정 지수로 명확히 표현했습니다.
문제 3. 매일 수집하는 데이터가 미래 예측에 활용되지 않는 문제
원인: 기존 시뮬레이션만 사용하면 다음 날에도 과거의 높은 주차 수요를 반영하지 못했습니다.

해결: SQLite에 누적된 조회 기록을 날짜별·시간별로 묶어 유사 요일, 주말 여부, 최근성, 공연·기상 조건을 반영하는 과거 사례 기반 보정 기능을 추가했습니다.

배운 점: 데이터가 많아졌다는 사실만으로 정확도가 높아지는 것은 아니며, 향후 날짜 단위 분리 검증과 오차 측정이 필요합니다.
문제 4. 웹사이트가 반복적으로 새로고침되는 현상
원인: 개발 중 반복 요청과 갱신으로 화면 상태가 자주 초기화되었습니다.

해결: 전체 화면 자동 새로고침을 제거하고, 현재 시간대 AI 카드만 정각에 갱신하는 방식으로 개선했습니다.

▶️ 실행 방법
1. 저장소 복제
git clone https://github.com/yeseongho/-88-parking.git
cd ./-88-parking

2. 백엔드 실행
cd backend
python -m pip install -r requirements.txt
python train_model.py
외부 API 인증이 필요한 경우 backend/.env에 개인 키를 설정합니다. .env 파일은 공개 저장소에 올리지 않습니다.

3. 프론트엔드 실행
다른 터미널에서 프로젝트 루트로 이동한 뒤:
python -m http.server 8765

브라우저에서 http://127.0.0.1:8765 접속. 로컬 테스트 시 config.js의 서버 주소 설정을 빈 문자열로 유지합니다.
python -m uvicorn main:app --reload --port 8000

⚠️ 데이터 해석 안내
1. 주차 API에서 제공되는 합산 주차대수는 전체 올림픽공원 모든 구역의 실시간 잔여 대수를 의미하지 않습니다.
2. 2,200대는 별도 안내 자료의 참고 기준이며 API 응답 자체에서 검증된 총수용량은 아닙니다.
3. 공식 API를 조회한 시각은 원본 주차 센서의 측정·갱신 시각과 다를 수 있습니다.
4. AI 예측 및 구역별 추천은 방문 계획을 위한 추정 정보로, 실제 빈자리나 입차를 보장하지 않습니다.
5. 현재 무료 Render 서버의 SQLite 파일은 재시작·재배포 시 유지되지 않을 수 있으므로, 장기 학습용 영구 저장소는 향후 구축 과제입니다.
